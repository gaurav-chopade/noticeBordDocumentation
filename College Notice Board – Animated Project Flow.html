1. The big picture

A browser talks to one Spring Boot API. Every request passes the security layer, then a controller, then a service, then MySQL. Click any box to see what lives there. Packets show requests going right and responses coming back.

Where the code lives

frontend/src

  • App.jsx: all routes, role guards
  • context/AuthContext: token + current user
  • services/api.js: every API call
  • pages/: Dashboard, NoticeForm, NoticeList…
  • pages/public/: Landing, Admissions…

backend/config

  • SecurityConfig: which URLs are open
  • JwtAuthenticationFilter: reads token
  • JwtService: makes/validates JWT
  • DataSeeder: demo users on 1st start

backend/controller + service

  • NoticeController → NoticeService
  • TargetPolicy / TargetMatcher: who gets it
  • NoticeScheduler: runs every 60 s
  • Notification / Email / Audit services

backend/entity

  • User, Notice, NoticeTarget
  • Department, NoticeCategory
  • NoticeRead, Acknowledgement, SavedNotice
  • Notification, AuditLog, Attachment

2. Registration and approval

Nobody picks their own approver. RegistrationService routes the request up the chain automatically. Choose who is applying and flip the switches to see where the request lands.

Account status

Try to sign in

Sign-in is rate limited (AuthRateLimiter). The status is only revealed after the password is right, so strangers cannot probe who has an account. Only APPROVED accounts receive a JWT.

3. Life of a notice

A notice moves through states. Pick who is acting, then try the buttons. Wrong role? The backend answers 403, exactly like NoticeService and NoticeAccessService do.

4. Who receives a notice?

A notice has one or more targets. A person matches a target when every filled-in field equals theirs. Add targets and watch the matching people light up. This is what the live recipient count in the form does (TargetMatcher).

Permission is also checked when the notice is saved (TargetPolicy): a teacher can only reach students of their own department, an HOD only their own department, the Principal / Admin anyone.

5. One request, step by step

What happens when an HOD clicks Approve on a teacher's notice: POST /api/notices/42/approve. Press play, or click any step.

6. Time, visibility and the public site

A background job (NoticeScheduler) runs every minute: SCHEDULED → PUBLISHED when the publish date arrives, PUBLISHED → EXPIRED after the expiry date. Drag the clock and switch visibility to see who can read the notice.
